# Prometheus and Grafana examples

Enable the control-plane chart's private metrics Service (`metrics.enabled=true`) and configure its namespace selector to permit only the trusted monitoring namespace. The metrics listener is HTTP and has no application authentication; network policy, namespace RBAC, and private cluster networking are its security boundary. Never route it through public ingress. CNI NetworkPolicy behavior must be validated in your cluster.

The API Service has Prometheus scrape annotations. With campaign metrics enabled, the scheduler exposes its own private Service and the operator chart can expose local recovery metrics. Configure Prometheus to discover annotated Services in the Kordex namespace, or use your Prometheus Operator's `ServiceMonitor` with namespace and release labels appropriate to your cluster. Apply both `prometheus/kordex-alerts.yaml` and `prometheus/kordex-operations-alerts.yaml` only after matching their `release` and namespace labels and reviewing thresholds against observed traffic.

Import `grafana/kordex-overview.json` for API request rate, 5xx rate, and latency. Import `grafana/kordex-operations.json` for due queue age, active reservations, blocked operation reasons, recovery safety blocks, and completed recovery duration. Scheduler logs and `kordex_scheduler_errors_total` use bounded `error_class`/`class` values and omit database messages. These are operational signals, not approved SLOs. Recovery-duration histograms include completed recoveries only; blocked operations remain visible through the scheduler snapshot and recovery-block counter. Metric labels deliberately omit organization, cluster, node, operation, and user identifiers.

Enable `metrics.enabled=true` on the control-plane Helm chart to expose API and scheduler metrics through private ClusterIP Services. Enable the same option on the operator Helm chart to expose its metrics. Both charts default to loopback-only metrics; when enabled they bind to the pod interface and install an ingress NetworkPolicy limited to `metrics.namespaceSelector`. Validate these policies with the cluster CNI and keep the Services off public ingress.

Both the dashboard and alert thresholds require validation with the installed Prometheus/Grafana versions, scrape interval, traffic volume, and organizational SLOs. No monitoring stack is installed by the Kordex Helm charts.
