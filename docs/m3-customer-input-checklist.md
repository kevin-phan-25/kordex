# M3 customer input checklist

The consolidated artifact intake and preflight procedure is in
[`m3-artifact-intake.md`](m3-artifact-intake.md). It validates each trust domain
separately, emits `PASS`/`FAIL`/`NOT PROVIDED`, and is mandatory before the
guarded lab `plan`, `apply`, or qualification `execute`. No real customer
artifact inputs are currently present in this repository.
The complete deployment gate, status snapshot, network-input schema, and
ordered customer approval steps are in
[`m3-deployment-readiness.md`](m3-deployment-readiness.md).
Use the owner-specific request and sign-off packet in
[`m3-customer-handoff.md`](m3-customer-handoff.md) to collect the required
materials.

This checklist collects customer-owned decisions needed before a disposable Debian 13 Trixie or RHEL 9.8+ M3 qualification profile can be provisioned; Ubuntu 24.04 is supplemental only. It
does not authorize GCP, Cloudflare, network, identity, or host changes. Keep
maintenance execution gates off until
the separately approved lab run reaches its reviewed preflight.

The proposed private route and mTLS boundary are described in
[`private-management-connectivity-architecture.md`](private-management-connectivity-architecture.md).

**Never send private keys, signing seeds, passwords, enrollment tokens, API
tokens, Cloudflare service-token values, SSH private keys, or database
credentials in Git, this document, chat, ordinary email, Terraform variables,
or evidence archives.** Transfer public trust and non-secret evidence through
an independently authenticated channel. Deliver secrets directly into the
approved secret store or protected local files used by their consumer; this
checklist uses placeholders and does not request secret values.

## Decisions not to request through this checklist

Do not ask the customer to send private keys, service-token values, passwords,
SSH keys, database contents, or bearer tokens. The customer retains these in
its own secret-management system. Request only public trust, opaque references,
verification results, and approval evidence through channels appropriate to
their sensitivity. No organization membership, cloud permission, or host
execution grant is implied by supplying this checklist.
