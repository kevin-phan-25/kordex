These are delivery conventions; where the executable contract accepts a path,
the manifest records that actual path. The M3 manifest stores paths relative to
`/secure/m3/customer-inputs.json` and each populated slot must have exactly
`reference`, `sha256`, and `expiresAt`. References must be safe relative paths
to regular files below `/secure/m3`; hashes are recomputed, and a hash is not
a signature or approval. `expiresAt` is RFC3339 or `null` only when the
evidence is not time-bounded. The manifest binds project, region, zone, lab,
canonical matrix digest, K3s version, exact image targets, package-policy
digests, and image-race acceptances. `fixtureOnly` must be `false` for real
inputs. Do not copy the checked-in synthetic example.

For each populated evidence slot, the standardized reference target is the
single regular evidence package `/secure/m3/evidence/<input-slot>.bundle`,
encoded in the manifest as `evidence/<input-slot>.bundle`. Each package binds
the source records and signatures for that slot; large release, package, or
OCI artifacts remain at the separately listed artifact paths and are referenced
by their signed manifests/digests. These paths are destinations only; this
packet has not created any of these files.

Use only protected file references for secrets. The artifact path map contains
paths and public identifiers, never credential values. The registry auth file
is separate, mode `0600` or stricter, and passed only by path.

Debian's official release information says Debian 13.8 was released on
2026-11-21 and that new installation images would follow. Google's Compute
Engine OS catalog identifies `debian-cloud` as the publisher project and
`debian-13` as the amd64 family; the lab Terraform profile requires an exact
image from `debian-cloud`, not a family alias. At the read-only catalog check

| Numeric image ID | `5913446147369107523` |

| Creation time | `2026-11-16T09:34:37.318-08:00` |
| Metadata description | `Debian, Debian GNU/Linux, 13 (trixie), amd64 built on 20261116` |

This is an available Debian 13 image, but it is **not approved for the required
13.8 baseline**: it predates the 13.8 release and its metadata does not prove
the installed guest point release. Do not approve or use it for M3. The
authoritative sources are [Debian's 13.8 release notice](https://www.debian.org/News/2026/20261121),
[Debian's current Trixie release information](https://www.debian.org/releases/trixie/),
and [Google's Compute Engine OS image catalog](https://docs.cloud.google.com/compute/docs/images/os-details).

The image owner must re-run these read-only catalog commands after Google
publishes an image built from the 13.8 point release:

```sh
gcloud compute images list --project=debian-cloud \
  --filter='name~^debian-13-trixie' \
  --format='table(name,id,architecture,family,status,creationTimestamp)'
gcloud compute images describe <exact-image-name> --project=debian-cloud \
  --format=json
```

Deliver the exact `selfLink`, decimal `id`, `architecture: X86_64`, image
project, family, status, creation time, license URI, metadata output, and a
signed owner approval. The approval package is the canonical JSON record,
detached owner signature, separate accepted-review JSON, and reviewer
signature at the image-approval paths above. The record must bind project,
platform profile, self-link, numeric ID, `osId=debian`, `osVersion=13`,
`pointRelease=13.8`, `architecture=linux/amd64`, package-policy SHA-256,
owner/approver identities, evidence reference, approval time, expiry no more
than 30 days later, and rationale. The `image-approver` and `reviewer` must be
distinct trusted identities. See the exact field validator in
`scripts/m3_readiness_binding.py::verify_image_approval` and
[`m3-readiness-plan-binding.md`](m3-readiness-plan-binding.md#exact-image-approval).

After a separately authorized deployment, startup must verify
`/etc/os-release` (`ID=debian`, `VERSION_ID=13`),
`/etc/debian_version` exactly `13.8`, and `dpkg --print-architecture` exactly
`amd64`. Each created boot disk must report the approved `sourceImage` and
`sourceImageId`; independent evidence must record those values and the live
guest checks before qualification. These checks are implemented in
`infrastructure/terraform/gcp/self-managed-lab/{server,worker}-startup.sh.tftpl`
and `scripts/self_managed_lab.py`. The current Terraform source permits only
the Google-published `debian-cloud` image; accepting a custom image would
require a separately reviewed repository change. No such image or approval
was created here.
